Workspace and interaction design

Visual direction refined 2026-11-12 · Reference mockups

Cluster-first entry · approved Phase 1C.1 direction

Approved on 2026-11-06: perform the entry, header and sidebar refactoring in 1C.1. Replace the marketing home screen with a searchable list of contexts loaded from the configured local kubeconfig sources. Selecting an existing context connects and opens its workspace tab. Closing every tab returns to that list. Merely loading the list does not connect to clusters or execute credential helpers.

Adding kubeconfig sources and managing connection configuration belong in Settings, alongside helper trust, appearance and cluster labels. The cluster list and tab-strip selector choose existing contexts; they are not add-cluster wizards. If no contexts are found, show a concise empty state with a link to Settings. There is no separate “Local validation workspace”, “Retained live workspace” or “Explore UI preview” in the product journey. Validation tools remain developer-only; never show fixture data as live cluster data.

Use a compact header with brand, cluster tabs, an existing-context selector, Settings and Ask AI; below it keep the active context, connection status and namespace visible. Show resource location once in the resource toolbar. Remove slogans, the “Cluster workspace” subtitle, raw preview IDs, development-phase labels and the inline environment-label editor. Environment labels are edited in Settings and displayed compactly on tabs. Tab overflow must leave cluster selection accessible.

Use distinct resource icons in left navigation rather than repeated diamonds. Keep text labels and visible selected/focus states. Decorative icons are hidden from assistive technology; collapsed entries have tooltips and accessible names. Unexplained dots must not stand for unavailable resource types.

Compact workspace controls

Use two header rows: global navigation, then the resource-navigation toggle, active cluster, namespace and connection status. The status opens a disclosure with context, source, last successful read and Reconnect/Disconnect. Reconnect reloads credentials; Disconnect stops the connection and closes its tab. Show Retry directly when recovery is needed and Cancel during connection; helper review and error text remain visible when applicable. Dismiss the disclosure with Escape or outside focus.

Refresh belongs beside the Pods heading, without a separate toolbar. Column headings stay visible within the scrolling table. Single-namespace rows omit repeated namespace subtitles. Phase dots supplement labels: Running blue, Succeeded green, Pending amber, Failed red and unknown grey. Keep readiness separate. Selected details use compact label/value rows with context and namespace visible. The separate Identity & source disclosure is removed following Phase 1C.2 UAT; object UID and metadata remain available in YAML.

Searchable namespace selector

The active namespace opens a dropdown with its own search field. Typing filters available namespaces; click an option or press Enter to select it. Arrow keys move through options. Escape or clicking outside dismisses without changing the namespace. There is no separate text field or Go button in the identity bar. Each cluster tab retains its own namespace and selection. If discovery is incomplete or denied, offer an explicit Use option for a valid typed namespace; a complete list does not invent matches. Keep the current explicit namespace available even when discovery does not include it.

Connection status and recovery

  • Gray dot + “Not connected” before an attempt or after explicit disconnect; amber progress indicator + “Connecting” during an attempt.
  • Green dot + “Connected” only after a successful authenticated API request for that explicit connection generation. Loading kubeconfig or constructing a client is not proof of connection. Connected does not mean every workload is healthy or every resource is permitted.
  • Red dot + a specific failure label when connection fails: “Authentication required”, “Unreachable”, “Certificate error” or a safe generic “Connection failed” when the cause is unknown. Do not label every error as an expired token.
  • Permission denial for a particular resource shows “Access denied” on that view and leaves other accessible resources usable. If the initial check is forbidden and no authenticated read has succeeded, show “Access restricted”; do not claim that credentials expired or that the cluster is fully usable.
  • After loss of connectivity, mark displayed data stale and show the last successful check time. Do not retain a green indicator indefinitely on the strength of an old read. Bound checks/retries; no background connections to unopened contexts.

Users perform OpenShift, AWS and Azure login or renewal themselves in their own terminal. The app explains the observed failure and offers Retry; it has no token-entry form, login command runner, embedded authentication terminal or browser/device-login flow. After external renewal, Retry reloads the selected kubeconfig source and credentials, rechecks helper trust if configuration changed and invalidates stale requests/targets as required by the architecture. Never replay commands or mutations when reconnecting.

Configured, approved credential helpers may retrieve credentials for an explicitly selected connection under the existing trust policy. This is separate from an app-managed interactive login. If a helper requires login or interaction, report that the user must complete it externally. Do not silently open a browser or prompt for credentials.

Phase 1C.1 is implemented. Later Phase 1C capabilities remain separate. The workspace refinement specification and validation report describe the current controls; historical mocks do not establish shipped resource capabilities.

Application shell and cluster identity

Use the selected explorer shell: independent cluster tabs, persistent cluster/context and namespace selectors, grouped resource navigation, resource workspace and bottom Sessions dock. Distinguish a namespace, all namespaces and cluster-scoped resources. Preserve navigation, filters, selection and scroll position independently per tab.

Users assign Local, Dev, Staging, Production or custom environment labels in cluster settings. Never infer environment from a context name. Display environment separately from connection state and observed alert counts. A disconnected cluster is not automatically unhealthy; unavailable/stale health data must be identified. Alerts require evidence, not a decorative badge. Text and icons supplement color.

Phase 1C.3e access-control investigation design

In this phase, move ConfigMaps and Secrets into Workloads after CronJobs. Configuration retains ResourceQuotas and LimitRanges. This changes sidebar placement only; resource identities, readers, tabs, namespace/Back behavior and Secret metadata-only safeguards remain unchanged. This supersedes their historical Configuration placement.

The access-control specification places ServiceAccounts and the four RBAC kinds in Access control, retaining Namespaces and Nodes under Cluster. Rules and subjects keep their boundaries; binding scope is distinct from a subject's namespace. Explicit Pod/account and binding/role/account links open the validated target capture and retain Back behavior. User/Group identities are inert strings. No effective-permission summary, token controls, permission-changing actions or Secret fetching belongs in this design. Delivery evidence remains in status and reports.

Phase 1C.3d storage investigation

The storage specification extends the existing compact inventory and Overview/YAML patterns to six storage kinds, with PVC-only Events. Explicit Pod → claim → volume → class links retain bounded Back and scope restoration. Distinguish name resolution, UID evidence and agreeing binding references; attachment or binding does not establish usable storage. Cluster-scoped lists retain the saved namespace. No mount, provisioner installation, Secret fetching or storage actions are available. See the storage validation report.

Phase 1C.3c namespace policy and configuration

The configuration specification extends existing compact tables with Namespace, ResourceQuota, LimitRange, ConfigMap and metadata-only Secret views. Preserve namespace-kind retention and Back behavior. ConfigMap Data uses escaped text and explicitly labeled base64; quota/limit views show configured and reported evidence without measured-usage or admission claims. Secret Overview exposes only allowlisted identity metadata, with no values, YAML or Events. Pod links resolve only on click. See the verification results.

Phase 1C.3b networking investigation

Reuse compact inventories, Overview, YAML and namespaced Events for the networking specification. Service EndpointSlices and explicit links connect Ingress → Service → EndpointSlice → Pod using the existing Back history. IngressClasses are visibly cluster-scoped, with the namespace chooser disabled and the previous namespace retained. Keep association, ownership and name-resolution evidence distinct. NetworkPolicy views show configuration without asserting effective connectivity. The validation report records agent desktop observations and open checks.

Phase 1C.3a workload views

StatefulSets, DaemonSets and Jobs reuse Overview, YAML, Events and related Pods; CronJobs use Overview, YAML, Events and Jobs. The 1C.3a specification defines exact inventory columns, controller-specific status semantics and CronJob → Job → Pod navigation. Preserve the approved compact resource layout, literal inputs and bounded Back behavior. Logs remains available on Pod details.

Workload investigation refinement

Pod and Deployment detail use compact evidence tables, structured Overview facts and a larger read-only YAML surface. Workloads includes the read-only ReplicaSets destination. Relationship links and Back validate captured UIDs. Namespace changes preserve the selected workload kind and clear old-scope evidence. Technical search fields preserve literal input, and intentional namespace results remain available. See the refinement specification, approved visual references and technical results.

Resource selection and keyboard behavior

Arrow keys move table selection. Resource shortcuts operate on the selected resource and its explicit connection/namespace, without needing a mouse click. Show shortcuts in a compact legend and command palette. Inputs, editors and terminals retain their own key handling; global actions must not intercept typing or terminal commands. Disable resource actions when no eligible resource is selected. Destructive actions still require confirmation.

Resource detail offers Overview, Events, Logs, YAML and Terminal where applicable. In Phase 2, Evidence links captured sources to the investigation. Full resource identity remains available even when table cells truncate. Log failures may use a red vertical gutter alongside the relevant line, with textual severity. Previous-container logs do not enable follow.

Log lifetime

Phase 1C.2 logs belong to the visible Pod Logs tab. Leaving it stops collection and releases history; returning loads fresh output. These logs have no bottom Sessions dock. Future terminals and port forwards require their own approved persistent-session workflow.

Global AI panel · Phase 2

Ask AI is a consistent global button on every page, including settings and non-resource views. Clicking it opens a resizable panel on the right, leaving the current page visible on the left. Closing it restores space without losing the page state. Do not replace it with a modal, bottom sheet or separate page on laptop windows. Opening AI does not automatically hide the resource list.

A new investigation inherits available cluster/resource context. On pages without a resource, show the current cluster or an explicit no-target state; request a target before cluster tools run. Existing investigations remain bound to their original target when navigation changes. Show that target and provide a deliberate start-new/rebind action; never silently retarget an ongoing tool call or conversation.

Show provider/model, effective override and read-only tool status. Findings cite evidence identifiers with collection timestamps and links to inspected status, logs, configuration or metrics. Separate observations, hypotheses, unknowns and next checks; do not equate increasing memory or exit code alone with a confirmed cause.

View redacted payload opens a preview of the sanitized context planned for submission. View sent payload shows the actual submitted context for a selected request, including collection times and provider/model metadata. These views never expose API keys or authorization headers. If context changes after review, refresh the preview; do not present an older preview as the sent payload. Use session memory by default rather than silently persisting payload history. Payload retention and sharing policy follow the security model. Describe actual filtering without promising that all sensitive data can be detected.

Log viewer

Opening Logs immediately shows one live current-container view. Keep container, Current/Previous, initial line count, Follow and Refresh controls. Previous uses a snapshot. Scroll all retained output, hold a stable reading snapshot when scrolling upward, and use Jump to latest to return. Search retained text with previous/next matches. Log rows scroll horizontally; very long lines continue on bounded display rows. Expand to window fills the application window; Restore size or Escape returns without reopening the reader. Remove Open logs, Clear view, Resume and Close. Display the initial line limit, 1 MiB retention bound and actual loss/errors. Rotated server history may be unavailable.

Themes and window sizes

UAT refinement approved 12 November 2026: launch maximized in the selected display’s available desktop work area, without entering macOS full-screen mode. Use the entire selected display work-area rectangle on the first native window show; keep ordinary resizing and saved pane proportions. Opening a Deployment’s Pods tab automatically advances up to eight empty ownership pages to find Pods; keep bounded Load more Pods only when continuation remains. Do not show internal traversal timestamps or completion labels. Inventory pagination places Previous, the page number and Next in one vertically centered group, with Auto-refresh aligned beside it and wrapping as a whole on narrow panes. Separate these controls from the filter row. Do not display the inventory capture timestamp in the table hint; retain stale-data warnings and detail evidence timestamps.

Appearance lives in Settings, not the workspace header. Default to System; support persistent Light and Dark overrides. System tracks OS changes. Theme switching preserves layout, sessions and selection. Dark uses neutral charcoal surfaces with blue interactions and separate green success indicators; Light retains its off-white/deep-teal palette. Both share the same hierarchy.

Dark surfaces progress from base #1A1D21 through panel #22252A, hover/selection #2C2D30 and floating overlay #35373B, with #383A40 dividers. Text uses #D1D2D3, headings #E8E8E8 and metadata #A3A5A8. Blue #1D9BD1 marks buttons and focus; lighter #6FC8F0 keeps interactive text readable. Success uses #2EB67D, warning #ECB22E and error text #FF839F. Primary blue buttons use dark text. Flat surfaces and textual status labels preserve meaning without relying on colour alone.

Drag the visible divider between the Pod list and details, including the empty Select a Pod pane, to allocate space. It moves left/right when panes sit side by side and up/down when they stack. A focused divider supports arrow keys. Remember width and height shares independently across restart; window-size clamping must not overwrite the saved preference. The divider remains available when the AI panel opens or closes.

Available space Behavior
Wide monitor Resource list, detail/evidence and right-side AI can sit side by side.
Laptop List and detail can stack within the main page; AI stays on the right. Keep both list and detail accessible without automatically collapsing the list.
Narrow supported window Use pane scrolling, compact controls and user-controlled navigation/dock collapse. AI remains on the right and the current page remains accessible.

Choose and verify minimum window/pane widths during UI implementation rather than shrinking text to fit. Clamp saved bounds and pane widths to the available display when moving between monitors or disconnecting one. Preserve state through resizing and OS scaling changes. Verify keyboard focus, contrast and scrolling at the smallest supported size. Static images do not establish these checks.

Operational review and errors

Review shows cluster/context, namespace, resource and intended action/diff. Switching tabs cannot change the target. Stale identity/state invalidates review. Explain disruption, hook execution and cluster-wide effects where relevant. Keep loading, empty, forbidden, disconnected, stale, unsupported and missing-dependency states distinct.

Delivery boundary

This approves the product visual direction, not a Phase 1A scope expansion. Phase 1A stays a minimal integration interface with clear targets and sessions; Phase 1B develops and validates the UI foundation, themes and adaptive layout using the approved mocks and clearly labeled previews; Phase 1C connects the full live explorer. See the UI milestone and approved UI specification. The global AI panel and evidence sharing arrive in Phase 2. UI libraries, exact breakpoints and accessibility measurements still require implementation validation.
