Workspace and interaction design

Proposed screen specification; visual design is still to be reviewed.

Application shell

Cluster tabs across the workspace; persistent context/cluster identity and namespace selector; grouped resource navigation; command palette and search. Distinguish one namespace, all namespaces and cluster-scoped resources. Cluster aliases and production labels supplement original context identity; color is never the sole identifier.

Resource workspace

Filterable resource table with selectable detail view. Overview, YAML, Events, Logs and Terminal appear where supported. Resource relationships link within the originating cluster. Preserve navigation and filters independently per tab.

Active sessions

A session area lists logs, terminals and port forwards with cluster, namespace, resource/container, status and stop controls. Switching tabs preserves sessions. Closing a tab with active sessions prompts for closure and cleanup; it must not silently detach operational sessions.

Action review

Show cluster/context, namespace, resource and intended action or diff. Switching tabs cannot alter an open review target. Changes to underlying identity/state invalidate review. Confirm destructive actions and describe workload disruption, hook execution or cluster-wide effects where relevant.

Metrics and AI

Charts identify source, time range, freshness and missing data. Phase 2 investigation lives beside the selected workload, shows provider/model and evidence sharing, and links findings back to captured source evidence. Users can inspect the reasoning evidence without accepting a suggested cause.

Settings and errors

Settings cover kubeconfig sources, trusted helpers and revocation, provider profiles/default/cluster overrides, monitoring endpoints, aliases, appearance and privacy. Distinct loading, empty, forbidden, disconnected, stale, unsupported and missing-dependency states provide a next step without suggesting permission bypass.

Design work still ahead

Review mockups, information density, keyboard behavior, component tokens and accessible contrast before building the shell. Candidate UI libraries are not yet selected. No mockup in this documentation represents approved application UI.
