Architecture

Wails + Go + React/TypeScript, subject to an early validation gate.

Selected approach

React/TypeScript handles presentation. Wails exposes narrow Go services and events. Go owns Kubernetes clients, operational policy and session lifecycle. Keep domain services independent of the desktop framework. Wails v3 is the proposed baseline; verify and pin a supported version at validation time.

Tauri 2 + Go sidecar was considered. It provides native capabilities and a separate backend process, but adds Rust integration, sidecar protocol/lifecycle work and per-architecture binaries. The user chose Wails for the Go-centered architecture. This is a documentation-based choice, not a performance result.

Boundaries

Component Responsibility
Frontend Navigation, tables, editors, terminal rendering, confirmations and transient UI state
Desktop adapter Typed request/event translation; native integration, no business logic
Application services Connections, sessions, operation preparation, cancellation and safe error mapping
Kubernetes adapters client-go typed/discovery/dynamic clients; exec and port forwarding; dedicated OpenShift adapters
Local settings Versioned preferences, context references, trust records and provider-profile references
AI services, Phase 2 Separate read-only evidence service, policy/redaction, provider adapters and citations

Connection identity

Each backend-created connection ID resolves a kubeconfig source/context and generation. Requests carry this ID and explicit resource identity: group/version/resource, namespace where applicable, name and UID/resourceVersion when relevant. Tabs own namespace filters and subscriptions; no operation uses a mutable global active context.

Do not change kubeconfig current-context. Credential/endpoint changes require re-evaluation: endpoint, CA or user changes invalidate pending actions and create a new generation. Never retarget an existing terminal or prepared mutation. Cache sharing is allowed only when complete connection/authentication identity matches and lifecycle isolation is preserved.

Authentication

Use Kubernetes kubeconfig loading semantics for default paths, KUBECONFIG and added files. Reuse configured tokens/certificates and trusted exec helpers rather than scraping cloud credential caches. Support helper-path configuration for Finder-launched apps; test expiry, missing helpers, externally completed login and reload. AKS may require a configured helper such as kubelogin. Honor configured CA/proxy settings; surface VPN/network failures distinctly. See the security model for trust rules.

Users own interactive login and renewal in their terminal. KubeSift does not run oc login, AWS SSO login or Azure login, accept pasted login tokens, or start browser/device-login flows. Approved kubeconfig credential helpers may retrieve credentials for selected connections; helpers requiring interaction fail with external-login guidance. Retry reloads the selected source and re-evaluates trust and connection identity. Authentication errors, transport/TLS errors and resource-level authorization failures remain distinct.

Resource access and operations

Discover scope, versions, verbs and subresources. Handle partial discovery and aggregated API failures without hiding accessible resources. Generic list/detail/YAML uses dynamic clients; specialized views enrich common resources. Watch only needed resources, handle expired resource versions with re-listing and show stale data on disconnection.

Use prepare/review/execute operations bound to target and payload. Use dry-run where supported; choose patch/apply semantics deliberately and surface field conflicts. Rollback is resource-specific and available only where usable history exists. Helm and Operators may affect resources outside the selected namespace; previews must disclose this.

Long-lived sessions

Watches, logs, terminals and port forwards have explicit session IDs, connection generations, states and cancellation. Event envelopes identify the session and sequence. Initial design uses typed bridge calls for control and batched events for data; validate throughput before selecting final transport.

  • Logs: container/previous-log choice, bounded tail, timestamps, ring buffers and visible truncation.
  • Exec: terminal input/output, TTY resize, backpressure and explicit disconnect; never silently discard input.
  • Port forwards: loopback by default, port-conflict handling, target/status display and cleanup. Payload traffic stays outside React.
  • Watches: batching, bounded queues, resynchronization on overflow and cancellation when unused.

Frontend listener removal is not backend cancellation. Confirm closing tabs with active sessions, then cancel owned work. Reads may reconnect after sleep; writes and commands must not replay automatically. Do not automatically retry a write with an uncertain outcome.

Metrics

Current usage comes from an existing Metrics API. Display CPU units and memory bytes; percentages name their denominator (request, limit or node allocatable). Historical charts use a selected existing Prometheus-compatible endpoint with required series. Report missing, stale, forbidden and unsupported data separately from zero.

Discovery suggests candidates; users can configure an endpoint when discovery is unavailable. Connections may use authorized API proxy, temporary port forwarding or configured HTTPS. Never forward cluster tokens to arbitrary discovered URLs. Bound query range, resolution, concurrency, timeout and response size. No metrics stack is installed by KubeSift.

Packaging and storage

Plan signed/notarized macOS distribution. Validate Finder launch, credentials, terminal rendering and cleanup in the packaged build. Minimum macOS, Intel/Apple Silicon coverage and updater mechanism are open. Use atomic versioned settings; provider keys belong in the OS credential store. Resource caches/logs are memory-only by default.

Validation and future source organization

The validation plan defines the first integration experiment. Suggested future modules: frontend, application services, Kubernetes/OpenShift adapters, security, sessions, settings and desktop adapter. No application directory is created by this planning work.
