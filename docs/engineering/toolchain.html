Build and verify

Run these commands from the repository root.

npm ci
wails3 task build
scripts/check.sh

The build generates the desktop bindings, frontend bundle and isolated Helm renderer. Both build and check tasks compile internal/helmrender/worker.wasm from the pinned SDK using Go's WASI target; the generated asset is ignored by Git. Before running raw Go test/build commands in a fresh checkout, run sh scripts/build-helm-renderer.sh. For the macOS packaging command and launch instructions, see the README. Local packages are ad-hoc signed.

Local cluster tools

Install Docker, kind and kubectl when running the approved integration fixtures. See Local development for the cluster contexts, fixture commands and validation boundaries.

Kubernetes and Helm compatibility

KubeSift bundles pinned Kubernetes client-go and Helm Go SDK dependencies. Updating a cluster or the Helm CLI on a laptop does not automatically require a KubeSift release, and the installed Helm CLI does not control the bundled SDK version.

  • Kubernetes patch releases normally need no application change. Review each minor release for new, deprecated or removed APIs. Use API discovery to handle available resources and show clear unavailable-feature errors; discovery alone does not prove compatibility.
  • Publish a tested Kubernetes version range and Helm release-format/storage coverage with release validation. Test representative versions on the approved local clusters and record exact versions and limitations. Do not claim every cluster, Helm major version or provider is supported merely because the client connects.
  • Review dependency updates regularly. Prioritize relevant security fixes, then needed bug fixes, API compatibility and features. A new upstream patch or minor version is a review trigger, not an automatic requirement to ship a new KubeSift version.
  • For an upgrade, check the Go requirement and compatibility between Helm and Kubernetes modules, update pins together where required, run the affected checks and packaged-app smoke test, and record verified coverage before release. Treat major Helm changes and Kubernetes API removals as explicit compatibility work.

Kubernetes publishes approximately three minor releases per year and regular patch releases. Older clients can work across multiple server versions, but new or removed APIs may limit features. See the Kubernetes release cycle, client-go compatibility guidance and Helm SDK documentation. No untested support range is promised here.
