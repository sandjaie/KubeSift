Capability inventory

Delivery commitments and explicit gaps, not a claim of competitor parity.

This is a requirements inventory from our discussion. It is not yet a sourced feature-by-feature comparison against specific Lens/K9s versions. Complete that comparison before freezing Phase 1 release scope.

Read-only configuration: Phase 1C.3c covers Namespaces, ResourceQuotas, LimitRanges, ConfigMaps and Secret identity metadata, with explicit Pod configuration links. See the validation report. Secret value reveal/YAML and broader configuration workflows remain deferred; do not count metadata-only browsing as complete Secret inspection.

Capability Status Acceptance focus
Multi-cluster tabs, kubeconfig, CLI credentials Required Concurrent connections; independent targets; credential renewal failures
Core resources + generic CRs Required Discovery, partial RBAC, supported verbs, absent API handling
Read-only Pods, Deployments and ReplicaSets Merged into develop through PR #7 Bounded inventory and UID-checked relationship navigation
Read-only Services, EndpointSlices, Ingresses, IngressClasses and NetworkPolicies Implemented in Phase 1C.3b Bounded, scoped networking reads and reference navigation; no connectivity or enforcement claim
Details, YAML, logs, events, exec, port forwards Required Correct container/target; bounded streams; explicit stop and cleanup
Edits, restarts, scaling, deletion, rollback Required Review, conflicts, exact target; no unsafe automatic retry
Helm lifecycle Required Install/upgrade/rollback/uninstall; values and hooks impact review
Node maintenance Required Eviction/PDB behavior; local data warnings; no default bypass
Current/historical CPU and memory Required when sources available Source/freshness labeling; no data vs zero; missing-source fallback
Dedicated OpenShift workflows Required Routes, Projects, Builds, Operators; API/version detection
AI providers and evidence-based diagnosis Phase 2 Provider profiles; citations and controlled sharing
Bulk actions, local shell, file copy, extensions Unresolved Explicitly include or defer during scope review
GitOps integrations, cost/security scanning Uncommitted Not implied by broad resource access
AI mutations/remediation Later, uncommitted Separate authorization and safety design

Future comparison entries must record competitor/version/source, user value, inclusion decision and a verifiable acceptance criterion. The roadmap owns ordering; this inventory owns capability coverage.
