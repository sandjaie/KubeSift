Delivery roadmap

Phase sequence lives here; execution tasks live in Superpowers plans.

Each increment ends in reviewable evidence and a usable outcome. Security and testing are continuous, not deferred to release. Dependencies below are the default order; changes require updating this roadmap.

PhaseScopeDependency / exit evidence
1A · ValidationMinimal Wails integration, packaged launch, auth, two cluster sessions, concurrent streams, terminal, forwarding and controlled local writeApproved spec and execution request. Pass validation gate or revise architecture before expansion.
1B · ExplorerDesktop navigation/settings, contexts, cluster tabs, discovery, core/generic resource views, YAML/events/logs and filtering1A. Failing-Pod inspection and partial-RBAC/disconnect journeys pass.
1C · OperationsYAML changes, restart/scale/delete, exec/port forwards, rollout history and supported rollback1B. Target isolation, conflicts, confirmations and session cleanup verified.
1D · AdministrationHelm lifecycle, current/historical metrics, cordon/uncordon/drain1C. Hook/cluster-scope review, PDB behavior, absent metrics and query limits verified.
1E · OpenShiftDedicated Projects, Routes, Builds and Operators workflows1B foundation and 1C safeguards; after 1D by default. Test actual supported OpenShift APIs and permissions.
1F · Release readinessCapability inventory closure, supported-environment tests, performance, accessibility, packaging, signing and release review1A–1E. Agreed Phase 1 scope met or explicitly deferred; no unsupported parity claim.
2A · AI foundationProvider profiles, secure keys, default/overrides, Claude adapter, read-only tool contracts, sharing/redactionPhase 1 service foundation. Validate provider routing and no credential/Secret leakage with synthetic evidence.
2B · InvestigationEvidence collection, metrics correlation, cited diagnoses, missing-evidence handling and evaluation scenarios2A. Failing-Pod AI journey passes with verifiable citations and no write access.
2C · Provider breadthOpenAI/OpenRouter and additional supported adapters, model capability handling and release hardening2A contracts and 2B evaluation. Provider-specific compatibility proven.

2A–2C are proposed subdivisions of the accepted AI phase. OpenShift connectivity and generic resources start in 1A/1B; 1E supplies specialized workflows. No durations are promised before validation.

Release gates

  • Record tested desktop, Kubernetes, OpenShift, Helm and authentication versions.
  • Set measurable performance budgets after 1A and assess them in 1F.
  • Use local disposable clusters for mutation tests; obtain exact company targets for integration checks.
  • Resolve license, signing, updates and public repository hygiene before publishing.
  • Keep AI remediation separate and uncommitted beyond Phase 2 investigation.
