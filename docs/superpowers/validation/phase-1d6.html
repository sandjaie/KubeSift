Phase 1D.6 interactive sessions validation

Tested on 16 November 2026 from develop 355ff0f. See the specification and plan.

Automated checks

Source and documentation checks, Go tests and vet, TypeScript typechecking, lint and 104 frontend tests passed via scripts/check.sh. Native kube/session race checks, Wails bindings, the production frontend bundle, macOS package and strict signature verification passed.

Synthetic tests checked Pod UID replacement, exact exec arguments, forbidden exec, input backpressure, resize, Stop before activation, the eight-entry cap, stale generation, Service selection, named and numeric TCP ports, partial candidate paging and occupied local ports. The frontend case verified registration before activation, stale and late events, idempotent activation, and release of cancelled or closed entries. A regression reproduced a stalled SPDY upgrade that would not stop while waiting for HTTP headers. The corrected upgrade uses the cancellable HTTP transport and carries the socket into the pinned client-go SPDY exec or forward protocol without retry.

Approved kind contexts

On kind-dev-local-a and kind-dev-local-b, both Kubernetes v1.37.0, ran KUBESIFT_INTERACTIVE_INTEGRATION=1 go test -tags=integration ./tests/integration -run '^TestInteractiveSessions$' -count=1 -v with isolated A/B kubeconfigs. Each context passed terminal input, remote TTY resize to 31 rows by 97 columns, normal exit, missing executable, direct Pod and named-port Service TCP requests, conflict detection and listener release. Session counts and pending bytes returned to zero. The fixture namespaces were deleted by UID.

Packaged macOS verification

  • On arm64 macOS 26.7.1, opened the A multicontainer Pod's selected shell and the B Pod's sole running container. Paste and Return produced distinct Pod names. Resizing the dock changed the remote TTY from 8 to 11 rows. Both terminals retained their output through cluster tabs, Settings, dock collapse and Light/Dark. A short background command's output appeared after restoring the app from Finder.
  • The B Pod forward returned the selected Pod's fixture response. The A Service showed two selectable TCP backends with different resolved ports. After explicit selection, the allocated loopback endpoint returned only that Pod's fixture response. The dock showed the Service, fixed Pod, actual local address, and Copy address. The occupied port and missing executable each produced a specific failure without a fallback.
  • One confirmation listed B's terminal and forward. Closing the tab released B's listener while A's still worked. Stop retained A's terminal entry and Close removed it. Quitting with the A forward active released its listener. The original Dark appearance and dock height were restored, and the UID-guarded fixtures and temporary kubeconfigs were removed.

After correcting cancellation during the HTTP upgrade, rebuilt and signed the bundle. A fresh terminal accepted input and reported its own Pod name, and a fresh Service forward returned the selected named-port backend. Quitting released the new listener. Both retest namespaces and their kubeconfigs were removed.

Kubernetes stream endpoints address Pods by name. The UID checks before, after and during setup reduce the race, but no atomic UID precondition is available. Closing a local exec transport does not guarantee every remote child exits. The short background walkthrough does not establish sustained WebKit throughput or a lossless transcript. No other platform, Kubernetes provider or context was exercised.
