Phase 1D.2 reviewed restart validation

Verified on 15 November 2026 from f7edda7 on the existing feature/phase-1d2-reviewed-restart checkout. See the restart specification and implementation plan.

Automated and live API evidence

  • Repository checks, operation and connection race checks, Wails bindings generation and production package build passed.
  • Synthetic loopback tests counted mandatory dry-run and at most one real PATCH. They covered exact patch replay bytes, both identity tests, late version conflicts, 422 diagnostics, 429, 401, redirect, EOF, 5xx, invalid success and changed admission spec. The shared coordinator tests covered cross-action token rejection, one active action per target, aggregate capacities, duplicate confirmation, expiry, revocation and retained result lookup.
  • TestReviewedRestart passed on kind-dev-local-a and kind-dev-local-b. Deployment, StatefulSet and DaemonSet dry-run left the source version and marker unchanged, and confirmation preserved sibling annotations. Accepted patches led to new controller-owned ready Pod UIDs in the local fixtures. Recreate required exact name acknowledgement. Paused, OnDelete and partitioned fixtures remained unchanged. Both clusters rejected independent stale version and replaced UID patches on all three kinds. Controlled credentials verified explicit denial and successful dry-run with an unavailable hint.
  • TestReviewedScaling and TestWorkloadInvestigation passed on both contexts. The read suite first reported the missing retained CronJob Job fixture and passed after the documented owned Job was provisioned. The historical marker integration uses other contexts and was skipped. Its unit coverage ran with the Go suite.

Packaged desktop evidence

  • The arm64 production bundle on macOS 27.0.1 confirmed Deployment and StatefulSet restart on A and DaemonSet restart on B. The modal showed the captured target, server dry-run, rollout impact and previous and proposed annotation. The Recreate action stayed disabled until the exact Deployment name was entered. Paused, OnDelete and nonzero partition cases displayed disabled reasons.
  • An external change to the owned Deployment after review produced a stale result. Open target read the current capture, and a fresh review confirmed successfully. The mixed results panel preserved a Scale count and restart timestamps alongside the stale row. Opening the DaemonSet target and using Back restored the prior Deployment.
  • Escape restored trigger focus. Keyboard navigation reached the review action. The review worked with the default System appearance and Light, a 29% detail split and native window zoom. Appearance and detail sizing were restored. The ControllerRevision inspector, ConfigMap Data, YAML toolbar and page-scoped Events controls remained available.

Native desktop verification exercised the stale outcome. Permission rejection, lost responses and changed admission behavior were verified with live API or controlled transport tests.

Cleanup removed the owned restart and scaling namespaces, the temporarily retained Jobs and their Pods in both contexts, and the isolated kubeconfigs used for integration.
