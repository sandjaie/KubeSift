Phase 1D.3 reviewed deletion validation

The specification and implementation plan define the eight workload routes and review safeguards. Verification used the existing checkout from 163848f on 16 November 2026.

Automated and API-server evidence

  • Repository checks, targeted Go race checks, binding regeneration, production packaging and strict signature verification passed. The final frontend suite ran 96 tests.
  • Synthetic HTTP and race tests exercised exact typed-name confirmation, fixed options, shared action locks and limits, bounded evidence, duplicate confirmation, connection closure after dispatch and uncertain responses. Check target covered all five states, including the distinction between an object-specific and ambiguous 404.
  • On both kind-dev-local-a and kind-dev-local-b, all eight workload routes accepted a valid conditional delete. Dry-run preserved UID, resource version, deletion timestamp and the representative Deployment and CronJob descendants. Background removal subsequently reached those descendants. Get-only permission was denied and a missing permission hint still allowed authorized dry-run. The unsafe StatefulSet policy was blocked in claim-free fixtures.
  • A scoped loopback relay introduced a version change or same-name recreation after the final GET on both API servers. Each server rejected the stale DELETE and preserved the updated or replacement object. A test-owned finalizer held the original Pod in Terminating until fixture cleanup. Operation-bound checks distinguished absence from the replacement UID.
  • Reviewed scaling, reviewed restart and workload investigation passed on both approved contexts. The historical marker integration was outside this validation. Its unit coverage ran with the Go suite.

Packaged desktop evidence

  • The arm64 bundle on macOS 26.7.1 worked with the standalone Pod on A and the Deployment on B. Escape revoked a prepared review and restored focus to Delete. A case mismatch left Confirm disabled. The Pod showed observed grace, its finalizer and the direct-delete PodDisruptionBudget warning. Confirming left it terminating and Check target reported that state.
  • The Deployment showed background cascade impact. A concurrent version change produced a stale result and Check target reported that the original UID was still present. A fresh review was accepted and a separate check reported absence. Native Scale and Restart results were present in the same session alongside Delete results.
  • The final build refused preparation using a get-only fixture role on A. On B, successful deletion preserved the captured inspector and its Back to inventory action when the original left inventory. Readback later reported a different UID. Refreshing the inspector kept the original identity, and the replacement opened only after selecting it in inventory.
  • Verification used Dark and Light, keyboard focus restoration and a 36% detail split. The original appearance and 44% split were restored. The existing YAML search, managed fields, copy action and page-scoped Events controls remained available.

Native walkthroughs exercised Pod and Deployment. The other six routes were checked through the API-server suite. The test-only DOM environment exercised programmatic invalidation independently of the packaged walkthroughs. Other operating systems remain unverified.
