Phase 1E.5 Node administration and Phase 1E exit

API proof before implementation

The five-task plan started from planning commit 4154a67. Both named contexts, kind-dev-local-a and kind-dev-local-b, reported Kubernetes v1.37.0. Each proof created a tainted synthetic Node with its own UID and a StatefulSet pinned to that Node. A fixture service account could patch only the named synthetic Node and could request eviction only in its private namespace.

Stale Node UID and resourceVersion tests rejected scheduling patches. Valid conditional patches changed and restored scheduling. Evictions with stale Pod UID or version left the Pod intact. A StatefulSet recreated the same Pod name with a new UID, and a request carrying the original UID failed. The fixture set the replacement Running and Ready and waited for the PDB controller to observe one healthy Pod and zero allowed disruptions. The API returned a budget-specific 429. Relaxing the budget allowed the conditional request.

Product operation and desktop evidence

Both contexts passed the opt-in protocol and administration tests. A reviewed Cordon and separate Uncordon changed the expected field. An unmanaged Pod blocked the entire drain before cordon. A budget rejection after cordon appeared in the retained progress and cancellation preserved the cordon. Replaying confirmation returned the original operation ID. In a fresh review after budget removal, eviction admission and subsequent Terminating state were observed separately.

The synthetic Nodes have no kubelet. After observing Terminating, the integration fixture removed its own StatefulSet and Pod with UID preconditions. The worker then observed the reviewed UID gone and verified final inventory. Empty synthetic Nodes completed independent drains without fixture-assisted disappearance. These tests establish API behavior and operator evidence. They do not establish kubelet shutdown or replacement workload readiness.

The signed arm64 macOS app ran with the restricted kubeconfigs. On A, the blocked review showed the cross-namespace impact, one unmanaged Pod and an uncordoned Node. Dismissing the review made no scheduling change. Cordon and a separate Uncordon each produced an observed result. In the compact light window, the typed Drain confirmation remained disabled until the Node name matched. After cordon the result showed the protected Pod waiting for its disruption budget. Switching to B, reopening Results and cancelling A’s drain retained its Pod name, blocked count and observed cordon.

In dark appearance an empty Node on B showed zero assigned Pods, completed drain and remained cordoned. Separate Uncordon reviews restored the synthetic Nodes. Current usage and Historical usage remained in Node Overview. The walkthrough used the keyboard action selector, restored System appearance and ended with zero open contexts.

Automated coverage and cleanup

Native tests cover paginated and incomplete inventory, ownership and temporary storage, conditional writes, review replay, authorization, canonical locks, worker limits, retry and stop decisions, external uncordon, replacement, late arrivals, disconnect and shutdown. Scripted transports provide fault evidence. Mounted frontend tests cover typed consent, discarded settings, blocked inventory and a late review after changing connections. Repository checks include source descriptions, documentation links, Go tests and vet, bindings normalization tests, frontend tests, lint and type checking. The native operation and desktop race suites, Wails bindings, production frontend build and packaged signature verification passed.

Administrative setup and teardown ran separately from product credentials. Cleanup used recorded identities. The final cluster inventories contained only the original control-plane Nodes and no fixture namespaces or cluster RBAC. The original host Node UIDs and scheduling states were checked on both contexts. The desktop test process finished and its private kubeconfigs and package copy were removed.

Independent review

The repository reviewer examined the entire change from 4154a67 to c47506f. KSF-001 (P1) added named Pod GET access checks for candidates and terminating Pods before token issuance and again before cordon. KSF-002 (P1) compares the entire scheduling response with the reviewed Node, allowing the intended field and server bookkeeping. Both regressions failed on the original candidate.

KSF-003 (P2) retains reviewed Pod outcomes alongside explicitly unreviewed final arrivals. KSF-004 (P2) distinguishes interrupted reads from blocked work and preserves observed progress. KSF-005 (P2) sends terminal Node results through the scoped detail refresh once, including partial and uncertain results. Regression coverage includes a blocked GET cancelled before eviction, a same-name replacement and repeated result polls.

The same reviewer cleared all five findings at d76b332. The final repository check passed 137 frontend tests. Native race tests, the post-fix two-context integration, bindings, production build and signed package verification passed. The full interactive walkthrough preceded independent review. The final rebuilt package launched, but the Mac was locked during the additional interactive pass. The automatic target refresh received mounted coverage. Both sets of desktop fixtures and private credentials were removed.

PR #31 squash-merged into develop as cd0a585. Its tree matches the final reviewed candidate.
