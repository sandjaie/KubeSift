Phase 1E.1 Helm inspection validation

Validated on 17 November 2026 Dubai time from develop at 18db1af. See the design and implementation plan.

SDK and build

Helm Go SDK v4.3.1 and the Kubernetes API, apimachinery, client-go and streaming modules at v0.37.1 compiled and passed the repository suite with Go 1.27.3. The Go module baseline remains 1.26.0. The dependency changes also include compatible YAML, protobuf and supporting library versions. The SDK ships under Apache 2.0 and the pinned module contains a license file without a separate NOTICE file. The app uses the SDK Kubernetes storage drivers and chart-value helper.

wails3 task bindings, the production frontend build, scripts/check.sh with 116 frontend tests, go test -race ./internal/helmreader ./internal/desktop, and wails3 task package passed. Strict signature verification passed for the local macOS bundle. The stripped executable was approximately 51 MB versus 48 MB for the prior Phase 1D.8 local build. This measures build size.

The fixture producers ran explicit helm upgrade --install and helm upgrade with --no-hooks. The Helm 3 archive passed the published SHA-256 check. Native desktop walkthrough

The signed production bundle started on arm64 macOS 26.7.1 with a PATH containing only /usr/bin:/bin, where helm was unavailable. macOS accessibility was disabled in the session. A separate signed test bundle used the same production renderer and native services, with a temporary DOM automation script injected into its actual Wails WebKit window. The production bundle contains no test harness. The full workflow ran with the same isolated PATH and an inherited HELM_DRIVER=configmap; the view still began in Secret storage.

  • Opened both context-specific namespaces and selected each storage driver. The same release name produced distinct records. The corrupt ConfigMap row carried its own error, while the usable release remained available.
  • Selected revision 1 and viewed overrides, computed values, exact stored manifest, hook definitions and notes. Opened the current ConfigMap from Resources, then used Back to release and confirmed the same revision remained selected.
  • Changed appearance in Settings, returned to the workspace and checked Light and Dark. Restored the saved preference. The exact-name filter showed an empty state, and the context B restricted credential showed a List denial without another driver.

The initial walkthrough exposed an empty metadata decoding defect. Kubernetes can encode a genuine empty list with items: null. The decoder now accepts that representation and still rejects an absent items field. Both live tests and the native walkthrough passed after the correction.

Coverage and remaining limits

The recorded producer versions and both local storage drivers establish representative Helm 3 and 4 coverage. Helm 2/Tiller and SQL storage are unsupported. Computed values are unavailable if the stored chart lacks its declared dependency trees or overrides introduce incompatible table shapes that Helm could log. Stored overrides remain readable. Helm SDK JSON decoding can round large values internally. Revision ordering uses exact decimal text. Current object links establish only the identity read at navigation time. Other clusters, historic chart formats, and OS-level accessibility and keyboard interactions were untested.

Before cleanup, both contexts still had exactly revisions 1 and 2 for each driver and no hook-created ConfigMaps. UID preconditions protected namespace deletion. Both namespaces, temporary kubeconfigs, the Helm 3 fixture binary and the desktop test bundle were removed.
