Phase 1C.2 · User UI UAT

All user results start Not tested. Agent evidence is separate in the technical report. This checklist does not authorize merge.

Prerequisites

Use only kind-dev-local-a/b, namespace kubesift-explorer. Fixtures: scripts/dev-clusters.sh --explorer. Preserve shop/billing. Open the locally packaged bin/kubesift.app; this is not a new release. 

kubectl --context kind-dev-local-a -n kubesift-explorer get pods,deployments
kubectl --context kind-dev-local-b -n kubesift-explorer get pods,deployments

Discover current web and completed-job Pod names from these lists. Use missing-setting, missing-image, same-pod, multi-container, init-evidence, web-lookalike, web and scaled-zero. Never alter normal credentials or delete shared workloads to manufacture a test.

Entered results are not persisted; reloading loses changes. Use the browser Print command and Save as PDF before closing, or print and fill by hand. Do not include workload/log payloads in public notes.

1. Cluster/namespace A/B isolation

Steps: Connect kind-dev-local-a and kind-dev-local-b. In each select kubesift-explorer and same-pod. Filter one tab; switch tabs.

Expected: Context, namespace, node and UID belong to the selected tab; filter, kind and selection remain independent.

2. Pod phase, readiness and reason

Steps: Select missing-setting, missing-image and a completed-job Pod.

Expected: Running can coexist with CrashLoopBackOff and 0/1 ready. Pending and Succeeded keep their distinct phase colours.

3. Deployment counts and zero replicas

Steps: Choose Deployments. Inspect web and scaled-zero in Overview.

Expected: scaled-zero shows desired/ready zero; observed status counters are zero, not failure or Unknown. Generations and conditions remain visible.

4. Page/filter/Refresh

Steps: Use Filter this page and Name sort. Refresh. Enable Auto-refresh. If a prepared namespace has >100 objects, inspect Next/Previous.

Expected: Filtering is explicitly page-local; Refresh returns to page one. Later pages pause auto-refresh. Large-page case is Blocked if no prepared fixture; do not create hundreds of objects.

5. Conditions and container groups

Steps: Inspect missing-setting Overview; then init-evidence and multi-container. Expand metadata and configuration.

Expected: Conditions, waiting/last termination, images, resources and probes are actual evidence. Regular/init/ephemeral groups stay separate; absent ephemeral containers are not invented.

6. Owned Pods and Back

Steps: Deployments → web → Pods → actual web Pod → Back to Deployment. Pods should appear without an intermediate loading click; use Load more Pods only if additional results exist.

Expected: Partial coverage is explicit. web-lookalike is excluded. Back returns to the captured Deployment, revalidating its UID.

7. Read-only YAML

Steps: Select YAML, search for metadata, use Find next, toggle Show managed fields, then Copy displayed YAML into a local scratch editor.

Expected: apiVersion/kind, UID and resourceVersion match. Both variants share captured time/version. Copy matches the visible variant; no Apply/Edit control.

8. UID events and empty/errors

Steps: Open Events for missing-setting and a healthy Pod; use Refresh section.

Expected: Events show reason/message/count/time and page-local ordering. No events does not claim no failure. Restricted-reader variant is Blocked unless safe isolated credentials are already prepared.

9. Automatic live logs

Steps: Select web Pod → Logs. Observe output immediately; turn Follow off for a snapshot.

Expected: One log box loads automatically. Current follows by default. The selected container and initial line limit are visible.

10. Previous and multi-container

Steps: Inspect missing-setting → Logs → Previous. Inspect multi-container and choose each named container explicitly.

Expected: Previous disables Follow. Available prior logs or honest server availability text are shown. Record unavailable previous evidence as Blocked, not Pass. The first regular container loads by default; selecting another replaces the view.

11. Scroll, search and expand

Steps: Scroll to the oldest retained output. Search for heartbeat; use next/previous matches. Expand to window, then press Escape.

Expected: Reading older text pauses automatic scrolling. Jump to latest returns to incoming output. Search highlights a match. Expansion preserves the reader and Escape restores the panel.

12. Leave and return

Steps: With live logs running, select Overview, then return to Logs. Repeat through Settings and cluster navigation.

Expected: Leaving releases the reader and retained output. Returning starts a fresh single view. No Sessions dock or duplicate log boxes appear.

13. Bounds and filter changes

Steps: Change container, Current/Previous and line count. Refresh. Inspect a prepared high-volume fixture if available.

Expected: Changes replace output in one box. Retention stays bounded to 1 MiB with visible omissions; all retained output is scrollable. Mark overflow testing Blocked if no safe fixture is prepared.

14. Layout, keyboard and saved splits

Steps: Use arrow keys/Enter to select rows, including first/last row. Resize list/detail split in current laptop/external layouts; revisit Settings and relaunch.

Expected: Repeated selection retains Overview. Compact header, searchable namespace, palette and saved independent splits remain usable; record actual dimensions.

15. Tab-close and exit cleanup

Steps: Close a tab with retained logs. Cancel once, then confirm Close tab and sessions. Close remaining sessions; quit and relaunch.

Expected: In-app confirmation lists affected tab/session count. Cancel preserves sessions; confirm removes them. Relaunch has no restored log payload. Replacement/reconnect race is optional and Blocked without prepared safe prerequisites.
