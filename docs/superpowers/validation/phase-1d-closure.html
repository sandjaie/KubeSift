Exit criteria and outstanding items

  • Reviewed operations: the reports show representative success for named creation, existing-object apply, editing, restart, scale, deletion and rollback. Apply and Edit use different server semantics.
  • Safety and authorization: evidence covers name collisions, stale versions and wrong UIDs, ownership conflicts, denied requests and uncertain responses. Reviewed targets are fixed; ownership takeover requires a separate server preview inside the same review; ambiguous writes are not replayed.
  • Sessions: the 1D.6 report verifies session ownership through navigation, deterministic Stop and Close, tab-close cleanup, and listener release at app exit. Terminal/forward integration was repeated during 1D.8.
  • Plan audit: 1D.1–1D.7 have no open task checkboxes. Phase 1D stays open until 1D.8 has passed independent review and merged. The historical Restart suite was not rerun with its legacy fixtures; its existing acceptance and the current shared operation regressions are separate evidence.

Scope and compatibility limits

Kubernetes stream URLs address Pods by name. UID checks reduce setup races without an atomic UID precondition. Closing the transport does not guarantee every remote child exits. Short packaged tests do not establish sustained WebKit throughput, a lossless transcript or behavior on other platforms or providers. The apply proof is limited to representative built-in and custom resources on the approved kind servers; it does not establish compatibility for every endpoint or Kubernetes release.

Bulk or multi-document operations, generated names, prune, arbitrary subresource actions, automatic rebase/retry, local-machine shells, releases, and Phase 1E are outside the committed Phase 1D scope. The audit makes no parity, provider completeness or distribution claim.
