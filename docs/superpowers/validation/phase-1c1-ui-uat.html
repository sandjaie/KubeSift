Launch and prerequisites

  1. Use only kind-dev-local-a and kind-dev-local-b. Start Docker if needed; preserve both clusters and existing resources.
  2. From the repository, build with wails3 task package if needed. In Finder open bin/kubesift.app. Quit an older instance first.
  3. The agent prepared kubesift-explorer on both local clusters. Discover actual Pods with the explicit commands below. same-pod is the fixed A/B identity case; Job/Deployment names have generated suffixes.
  4. If using a fresh machine, follow local development, then run scripts/dev-clusters.sh --explorer. That command only expands fixtures in the two existing clusters. 
kubectl --context kind-dev-local-a -n kubesift-explorer get pods
kubectl --context kind-dev-local-b -n kubesift-explorer get pods

# Optional isolated source copies; private files stay in ignored .local storage.
mkdir -p .local/phase1c1
umask 077
kubectl --context kind-dev-local-a config view --minify --raw --flatten > .local/phase1c1/uat-a.kubeconfig
kubectl --context kind-dev-local-b config view --minify --raw --flatten > .local/phase1c1/uat-b.kubeconfig

Add those absolute paths in Settings. Never publish their contents. Restricted helper/auth/capacity scenarios are optional unless a safe fixture is prepared; mark Blocked and explain the missing prerequisite. Do not disrupt normal kubeconfig or real cloud credentials.

Test session

UAT-01 · Startup and selection

Prerequisite: Packaged app; no previous instance running.

  1. Open bin/kubesift.app from Finder.
  2. Confirm the Clusters page has 0 open contexts. Search for kind-dev-local.
  3. If no contexts appear, choose Configure sources and add the isolated local kubeconfig path.

Expected: No preview, marketing or validation choices. Contexts are Not connected until selected. A missing source has a visible error and Settings link.

UAT-02 · Connect local A

Prerequisite: kind-dev-local-a available.

  1. Select kind-dev-local-a.
  2. Wait for Connecting to become Connected, then choose kubesift-explorer in Discovered namespace (or enter it in Manual namespace and press Go).
  3. Select same-pod.

Expected: A single A tab shows real Pods. The detail identifies A / kubesift-explorer, a nonempty UID and marker local-a. Failed fixture Pods do not turn the connection red.

UAT-03 · Independent local B

Prerequisite: A is open on same-pod.

  1. Choose cluster, then kind-dev-local-b.
  2. Set B to kubesift-explorer and select same-pod.
  3. Switch between A and B.

Expected: B has marker local-b and a different UID. A retains its own namespace, filter and selection. Neither tab displays the other cluster’s data.

UAT-04 · Focus existing context

Prerequisite: Both tabs open.

  1. Choose cluster and select A again.
  2. Repeat for B.
  3. Enter Settings and return using Back to workspace.

Expected: Existing tabs gain focus without duplicates. Namespace and selected Pod remain associated with the correct tab.

UAT-05 · Discovered and manual namespaces

Prerequisite: A open; optional prepared restricted source for extra check.

  1. Use Discovered namespace to choose default.
  2. Enter kubesift-explorer in Manual namespace and press Go.
  3. Optional: connect the prepared pod-reader source, first in default, then kubesift-explorer.

Expected: One explicit namespace is visible. Allowed manual reads work. Restricted source cannot list namespaces/default Pods but can read fixture Pods; it never claims a complete namespace inventory.

UAT-06 · Filters, empty and bounded lists

Prerequisite: Fixture Pods loaded.

  1. Filter Pods with same-pod, then a name that does not exist.
  2. Clear the filter and press Refresh Pods.
  3. Optional only if a prepared namespace exceeds 100 Pods: open that namespace. Do not create a flood for UAT.

Expected: Filter affects only this tab. No match and empty namespace are honest empty states. Over-capacity reads display the pagination limitation rather than a complete-looking truncated list.

UAT-07 · Independent sources and source errors

Prerequisite: Use isolated copies prepared below, never edit normal kubeconfig.

  1. In Settings add an absolute isolated A kubeconfig path not already configured.
  2. Add an intentionally nonexistent path under .local/phase1c1.
  3. Reload the added valid source, then return to the cluster list.

Expected: Equal context names remain distinguishable by source. Missing source error remains visible; valid sources and unrelated connections remain usable. No connection starts merely by adding or reloading.

UAT-08 · Remove, disable and restore

Prerequisite: A disposable added source has an open tab.

  1. In Settings press Remove for that source. Check affected context names; press Cancel.
  2. Repeat and Confirm. Verify its tab closes and its kubeconfig file remains on disk.
  3. Re-add the file. Optionally Disable/Restore default source after checking affected tabs.

Expected: Cancel preserves connections. Confirm closes only the source-owned tabs/work. Removing metadata never deletes kubeconfig; default loading can be restored.

UAT-09 · Labels and target review

Prerequisite: A disposable added source available.

  1. In Settings save a label for A. Return to Clusters and its tab.
  2. Restart and confirm the saved label.
  3. Optional safe fixture only: change endpoint or user identity in a separate disposable source copy, then Reload. Do not edit real credentials.

Expected: Only user-assigned labels appear. Changed identity suppresses the old label and requests review. A stale target cannot silently continue as the newly configured cluster.

UAT-10 · Appearance and restart

Prerequisite: Any page; note original appearance to restore afterward.

  1. In Settings select Light, Dark and System.
  2. Choose your preferred appearance, quit and relaunch the packaged app.
  3. Check the chosen appearance and source settings remain; reopen a context explicitly.

Expected: Saved appearance and existing pane preferences survive. Source operations do not reset appearance. Connections are not automatically restored on launch.

UAT-11 · Helper review and revocation — optional

Prerequisite: Requires a prepared harmless synthetic helper source. If absent, record Blocked; do not approve unfamiliar or real cloud helpers for this test.

  1. Select the synthetic helper context; open Review helper in Settings.
  2. Inspect executable/source and redacted argument/environment fields. Approve helper, then explicitly Connect.
  3. Revoke the test helper approval after reading its close-all warning.

Expected: Unapproved helper does not run. Approval itself does not connect. Explicit Connect runs only approved retrieval. Revocation closes all owned connections and changes displayed states. Changed helper configuration requires review.

UAT-12 · External renewal and Retry — optional

Prerequisite: Requires a controlled synthetic authentication fixture. If absent, record Blocked.

  1. Observe the prepared authentication rejection.
  2. Have the fixture’s credential file renewed externally without changing a real account.
  3. Press Retry in the affected tab.

Expected: Failure says authentication was rejected and directs external credential refresh. Retry rereads only that source and replaces the old generation. No login terminal, token form or automatic command replay appears.

UAT-13 · Connection failures and stale evidence — optional

Prerequisite: Use an isolated prepared unreachable/TLS fixture; healthy clusters stay running.

  1. Select the isolated failing context and read its status/explanation.
  2. Cancel a pending connection, then ensure it does not reopen later.
  3. For a prepared controlled transport loss, observe stale/error status after prior success.

Expected: Timeout, unreachable, certificate and authentication failures are distinct from forbidden resource access. Old success cannot remain green indefinitely. No instruction to bypass TLS validation appears. Do not stop either shared cluster.

UAT-14 · Navigation, keyboard, layout and AI

Prerequisite: Healthy A/B tabs. Use your normal laptop or external-monitor window size.

  1. Use arrow keys and Enter to select Pods. Press Cmd/Ctrl-K outside an input, then Escape. Try it while typing in Filter Pods.
  2. Visit a Soon resource destination and return to Pods.
  3. Toggle Ask AI / Hide AI on Clusters, workspace and Settings; test its × close button.

Expected: Distinct icons have text. Selection/focus work; input typing does not launch commands. Unavailable kinds show no synthetic data or operations. AI states future availability and sends no data. Explicit context/namespace remain readable; no exhaustive resizing required.

UAT-15 · Disconnect, close and relaunch

Prerequisite: Two open local tabs; no external contexts.

  1. Disconnect A and confirm B remains usable.
  2. Close the final tab with ×; reopen a local context.
  3. Quit, relaunch and verify 0 open contexts. Remove disposable test sources and restore original appearance/default-source preference.

Expected: Closing the last tab returns to Clusters. No hidden validation workspace or sample sessions remain. Reopening is an explicit fresh connection; no terminal input, mutations or forwards replay.
