Live local evidence

Only kind-dev-local-a and kind-dev-local-b were accessed, each with an explicit context and isolated configuration. Both servers report Kubernetes v1.37.0. Initial discovery found no Metrics API on either. A received an explicit development fixture; B retained its absent-provider state. The shipped application has no provider setup path or extra dependency.

The opt-in TestCurrentMetrics passed. A read-only loopback recorder captured the same real sample returned to the native reader; rational comparisons matched Pod and Node CPU/memory exactly. One captured Pod sample was 0m, 405504 bytes at 2026-11-19T11:44:57+04:00; a Node sample was 260.484068m, 1774043136 bytes at 11:45:14+04:00, served by metrics.k8s.io/v1beta1. Same-name Pods had distinct UIDs on A/B. A namespace-limited synthetic reader could GET the Pod but received metrics Forbidden. B returned unsupported/absent API while ordinary Pod reads succeeded.

Independent kubectl --context kind-dev-local-a top output rounded both pause containers to 0m / 0Mi and the Node to 261m / 1691Mi. These are differently timed, rounded samples; they are not claimed to be simultaneous exact comparisons. Rare malformed/partial/old samples were checked deterministically, not claimed as live provider output.

Fixture guards passed: unsupported context, pre-existing collision and replacement UID cleanup all refuse mutation. Limits

Physical machine sleep/resume, a separately captured in-flight desktop disconnect cancellation and other operating systems were not exercised; native re-entry and deterministic wake/cancellation paths were checked. No per-container runtime restart identity is claimed: Kubernetes metrics often omit UID/runtime ID, so the current core UID and sample interval provide the documented name-reuse guard. There are no historical metrics or new graphs. No release was produced.
