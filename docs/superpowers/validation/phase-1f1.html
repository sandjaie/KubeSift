Phase 1F.1 · OpenShift Projects

Feature branch based on planning commit 4cc1602. OCP 4.21 acceptance remains open.

Native and desktop evidence

Each approved kind API server returned seven core Namespaces and no OpenShift Projects capability. The opt-in integration read through the production service with explicit kind-dev-local-a and kind-dev-local-b connections.

Loopback tests cover empty, 130-item and 501-item responses, list denial with named GET, mismatched UIDs, exact quota quantities and independently scoped personal access. Before the generic YAML guard, preparing a ProjectRequest sent one POST. The corrected regression requires zero. Dedicated request tests cover revoked and production-labelled tokens, duplicate confirmation, 403, 409 and 500 responses and named readback. Conditional deletion tests inspect the UID and version in both DELETE bodies, typed acknowledgement and version drift before execution.

Mounted React tests exercise explicit lookup, inspection without scope changes, typed deletion, cancellation, two tabs using the same name, same-name UID binding and failed transitions. The frontend suite passed 139 tests. Wails bindings, production build and ad-hoc signed package were generated. The repository check and native race commands are recorded in the plan ledger.

The packaged macOS app connected to the TLS loopback fixture with Namespace and Pod lists denied. The Project header labelled the configured namespace unverified. Named lookup showed team-a and its UID. Quotas showed two Pods used of twelve. Personal checks reported denied, allowed and allowed. For team-b the quota request was denied and access results were unknown. Use project and keyboard entry both landed on scoped Pods with the expected denial. Command search reopened Projects. Request review showed the captured cluster and template warning and was cancelled. Deletion review showed the original UID/version and disabled confirmation until the typed name matched. Light and dark appearance were exercised and System was restored. Narrow-window verification remains open.

Live acceptance outstanding

No OCP context, identity, disposable name scope or cleanup authority was provided. Live acceptance requires restricted visibility and named selection without Namespace list, real quota and SSAR evidence with independent denials, a single confirmed request and observable template effects, a dry-run preserving the original nonterminating UID, rejection of stale preconditions on a disposable replacement, and confirmed deletion observed as termination or absence. Record the server build, identity roles and actual cleanup, including a separately authorized verifier if read access is lost.
