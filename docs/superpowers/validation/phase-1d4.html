Phase 1D.4 YAML editing validation

Verified on 16 November 2026 from develop f3819d7. See the approved specification and implementation plan.

Automated verification

Repository checks passed, including Go tests and vet and 101 frontend tests. The native operation race suite, Wails bindings, production frontend build, macOS bundle and strict signature verification passed.

Synthetic tests checked advertised routes and authorization errors, exact numeric values, server-owned field omission, Secret stringData precedence, strict dry-run and conditional request bytes. They verified that concurrent operations share the same target lock and that repeated confirmation and ambiguous transport outcomes generate no second write. The editor state test exercised cancellation, revocation of a late preview and confirmation of the original target only.

Approved local API servers

The opt-in YAML editing test passed on kind-dev-local-a and kind-dev-local-b. Each run exercised Deployment, ConfigMap, Secret, Service, an installed Widget and the disposable Namespace used to hold the fixture objects. The suite verified allowed saves, dry-run isolation, denied Patch for a get-only identity, immutable ConfigMap rejection, and a stale Namespace edit after an external change. It verified writes by reading the actual resources.

Packaged macOS verification

  • On the arm64 bundle for macOS 26.7.1, opened a context A ConfigMap, changed its YAML, and saw the unsaved discard warning. Kept the draft while connecting to B, resumed it on A, reviewed the actual line diff and dry-run, confirmed, and saw the updated value in the existing YAML viewer.
  • Opened a context A Secret through Reveal YAML, switched directly to editing and saved a stringData change through the same review. Reopening displayed the new base64 value. Closing the editor removed the revealed content from the view.
  • The context B get-only fixture could open the ConfigMap and received Kubernetes Forbidden during review. On A, a version change after dry-run made confirmation stale. Server reads verified the stored ConfigMap and Secret values and that the denied and stale changes did not persist.
  • Observed the YAML editor within the existing split layout in both Dark and Light and restored Dark. Used TypeScript and API tests for routing coverage beyond the two native examples. Removed the test-owned namespaces and temporary kubeconfigs and checked cleanup on both approved contexts.

The app keeps one unsaved editor across cluster tabs. Synthetic tests cover ambiguous writes. This run did not exercise OpenShift, other operating systems, or an external Kubernetes context.
