# Phase 1F.1 · OpenShift Projects

## Outcome and compatibility target

A developer who can see a Project in OpenShift can find it in KubeSift, inspect its status, quotas and their own access, and use it as the working namespace of one connection tab. An authorized developer can request a Project through the cluster’s self-service process. An authorized operator can review and delete a specific Project. The [product requirements](../../product/requirements.html) own these lifecycle operations. Routes, Builds and Operators have later workflows.

Use OpenShift Container Platform **4.21** as the first validation target and the cluster-scoped project.openshift.io/v1 API as the contract. This is a planning choice, not a verified support claim. Discover capabilities at runtime. No new OpenShift client dependency, oc subprocess, cluster installation or kubeconfig change. The [roadmap](../../roadmap/roadmap.html#phase-1f) owns the real-environment compatibility gate. Baseline is develop at `6cd1d19`. [Red Hat 4.21 Project APIs](https://docs.redhat.com/en/documentation/openshift_container_platform/4.21/pdf/project_apis/OpenShift_Container_Platform-4.21-Project_APIs-en-US.pdf)

## Discovery, visibility and navigation

Use the owned connection’s bounded native discovery/transport. Discover the exact group/version and cluster-scoped projects/Project and projectrequests/ProjectRequest independently, respecting advertised verbs. Missing request support disables only request creation. A confirmed absent Projects API omits the Projects entry from navigation and command search. Discovery forbidden, transient failure and list denial are distinct from absence. If availability is unknown, keep ordinary Kubernetes navigation usable and expose the reason and a retry through the existing API discovery surface. Invalidate per-generation capability state on refresh/reconnect. No repeated probes from individual rows.

Add Projects under a capability-driven OpenShift group using the existing compact sidebar and split detail. Replace the disabled OpenShift placeholder. Preserve Cluster → Namespaces and the generic installed-API browser. List visible Projects from GET /apis/project.openshift.io/v1/projects. Never derive membership from the core Namespace list, RoleBindings or context name. Empty means no Projects were returned for the caller. Named GET by explicitly entered valid name remains possible when list is denied, incomplete or too large and get is available. Reject mismatched identity or scope. No speculative GET on each keystroke.

Request 100 rows per page, at most 500 projected entries in memory for the active view, 16 MiB per decoded HTTP response, 30 s per read. Support real continuation when present. The 4.21 proxy can ignore pagination options and return a filtered list at once. For an oversized but decodable list report the cap and partial coverage; never declare a clipped list complete. For an oversized body, reject before decoding and offer named lookup. Never retain raw Project or Namespace bodies. [OpenShift Project proxy](https://github.com/openshift/openshift-apiserver/blob/release-4.21/pkg/project/apiserver/registry/project/proxy/proxy.go)

Selecting a row only inspects it. **Use project** re-reads the named Project on the captured generation, verifies UID and active/non-deleting status, then commits its name through the existing per-tab namespace transition. Land on Pods for that scope, or show the existing denied state if Pods cannot be listed. Make the same transition usable when the previous namespace’s Pod probe and cluster Namespace list are forbidden. Showing a Project never establishes Pod access. On confirmed OpenShift tabs, reuse the identity-bar selector with Project labels, Project-sourced suggestions and named verification on commit. Preserve explicit namespace choice and existing semantics on ordinary Kubernetes tabs. The cluster-scoped Projects page can switch via its detail action even when the identity-bar control is disabled. A configured namespace that has not been verified as a Project is labelled as such and excluded from visible membership suggestions. Verify and bind a UID even if the name equals the current namespace string. Commit the verified scope atomically for that tab; on a failed transition preserve the previous valid scope. Helm, related-resource navigation and Back must either restore and revalidate the captured Project or clear its binding when switching by namespace. Discard late work after switch, disconnect, reconnect or same-name replacement; bind selected Project identity as well as its name. If revalidation is denied, clear previously visible evidence. If a selected Project is observed to disappear or its UID changes, clear its evidence and require an explicit choice before reusing that project-bound scope. Do not silently select another project.

## Detail and permissions

Show canonical project name, display name and description from the OpenShift annotations, UID, creation time, phase and deletion timestamp when available. Render text as untrusted plain text. Limit display name to 256 characters and description to 2,048 characters in projected metadata, with visible truncation. No raw annotations, templates or credentials in retained results. Show unknown phase explicitly.

Load quota and access sections independently on demand for the captured project. Use existing core/v1 ResourceQuota readers/projections in that namespace for hard/used quantities and existing pagination. Label these **Namespace resource quotas**; absence of visible items says nothing about cluster-wide applied quotas. Access means **my access**, with scoped SelfSubjectAccessReview for list pods and list resourcequotas in this namespace, and delete on the named cluster-scoped Project. Report allowed, denied or unknown with capture time. These checks do not enumerate members or promise continuing permission. Recheck selected Project UID/access around ancillary reads and discard previous data on stale target or denial. Each section fails independently. Never edit quotas, roles or grants from this increment.

## Reviewed lifecycle

Use the existing Go coordinator, five-minute single-use review tokens, bounded results, current connection generation and native permission enforcement. Bind action, exact project name, payload, UID/version where available and confirmation policy. Use one canonical name lock across dedicated request/delete and existing core Namespace/OpenShift Project operations that address the same logical target. A repeat confirm returns the existing outcome. Revoke previews on relevant edits, navigation or recapture. Confirmed work has its own lifetime. Do not auto-replay an ambiguous write.

**Request project.** Validate a DNS-label name under Kubernetes Namespace rules, reject OpenShift-reserved names/prefixes per target server contract, and bound optional displayName and description as above. No arbitrary template, namespace, user, role or YAML input. Use the self-provisioning check GET projectrequests when supported; it returns Status, not membership. When that check is unavailable use a scoped SelfSubjectAccessReview for create projectrequests; a definitive denial blocks, and unresolved permission yields an unavailable action. Final authorization belongs to the POST. No cluster-wide Namespace listing prerequisite.

Preparation is local validation plus read-only permission evidence. Show the exact cluster, name, display name and description and explain that the server’s configured project template may create resources and grant access. KubeSift cannot enumerate its effects from the request. Do not POST a ProjectRequest during review, even with dryRun=All: the 4.21 delegated implementation calls downstream creates with fresh options. Guard the existing generic YAML Create path for this exact group/resource before its dry-run POST and direct users to Request project. Keep other resources on their existing review paths. On deliberate confirmation send exactly one POST of kind ProjectRequest with top-level displayName/description. No direct Project or Namespace create fallback. A definitive AlreadyExists is a conflict. A server error after template processing may leave partial effects. Surface that uncertainty, perform only read-only follow-up and never automatically clean up or resubmit. Show submission, returned Project identity and verified named readback separately; successful creation can precede readable access. Never infer ownership from a subsequent same-name GET after an ambiguous outcome or switch scope automatically. [OpenShift delegated ProjectRequest storage](https://github.com/openshift/openshift-apiserver/blob/release-4.21/pkg/project/apiserver/registry/projectrequest/delegated/delegated.go)

**Delete project.** Prepare from a named GET with verified UID and resourceVersion. Show cluster, exact name, phase and a plain-language warning that deleting the Project removes its namespace and its contents, including resources the caller cannot list. No exhaustive impact enumeration or zero-resource promise. Reject an already terminating target as a new deletion. Use the exact named Projects DELETE with DeleteOptions UID and resourceVersion preconditions and mandatory server dry-run (All). Require the typed canonical name for all environments. After confirmation dispatch the same conditional request once without dry-run. No Namespace fallback, forced finalization or collection delete. Treat acceptance, still terminating, observed original UID gone, replacement, forbidden and unknown as distinct outcomes. A 403 never proves disappearance. Require fresh review on conflicts. Clear affected captured views while keeping other tabs usable.

## Evidence and completion

Prove absent APIs on both approved kind contexts and simulate limited membership, ignored pagination, access changes, same-name replacements and write counts with deterministic HTTP tests. Contract fixtures can verify desktop workflows. They cannot establish OpenShift support. Use an explicitly authorized isolated 4.21 environment for live verification. Authorization must identify context, permitted identity/reads, disposable project names or prefix, allowed request/delete operations and cleanup. Do not discover targets by enumerating other kubeconfigs. With no external authorization, complete independent code, tests and packaged checks and record the unrun live gate. Do not mark compatibility verified or the increment complete until the live acceptance cases in the [plan](../plans/2026-11-22-phase-1f1-openshift-projects.md) pass. Phase 1F remains open for its other workflows.
