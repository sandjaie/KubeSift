# Phase 1D.2 — Reviewed workload restart

Planning only; implementation belongs in a separate session. Owners: [roadmap](../../roadmap/roadmap.html#phase-1d), [security](../../security/security-model.html), [UX](../../ux/workflows.html), [scaling contract](2026-11-14-phase-1d1-reviewed-scaling-design.md) and [verification](../../engineering/engineering.html#agent-verification).

## Outcome and chosen scope

Restart one inspected apps/v1 Deployment, StatefulSet or DaemonSet through the existing review/results flow. A restart changes the Pod template annotation and requests controller reconciliation; it is not container exec, Pod deletion or proof of readiness. Reuse the tested scaling safeguards and current resource-detail UI, including the PR #16 Overview/YAML/Events/ConfigMap refinements.

Choose conditional template annotation patching over direct Pod deletion: it uses the workload's controller strategy, does not need Pod delete permission and preserves ownership semantics. A generic YAML editor would expand field ownership and review scope beyond restart. No delete/evict, bulk actions, rollback, strategy edits, scaling changes, custom-resource writes, shell/exec, metrics, Secret reveal or release in this increment.

## Eligibility and impact

| Kind | Eligible | Review evidence and restrictions |
| --- | --- | --- |
| Deployment | Not paused or terminating; RollingUpdate or Recreate strategy | Strategy, desired/ready counts, maxSurge/maxUnavailable when applicable; Recreate warns all existing Pods can be terminated before replacements |
| StatefulSet | RollingUpdate and partition absent/zero; not terminating | Desired/ready counts, ordered update behavior, partition and returned rollout settings; unavailable Pod readiness can stall progression |
| DaemonSet | RollingUpdate; not terminating | Desired/current/ready scheduled counts and maxSurge/maxUnavailable; placement is controller-managed, not a selectable list of nodes |

Paused Deployment, OnDelete StatefulSet/DaemonSet, nonzero StatefulSet partition, unknown strategy and malformed/missing required evidence disable Restart with an explanation. Native preparation rechecks eligibility even if the UI offered the action. Do not resume, change partition/strategy, delete Pods or bypass the restriction. Omitted optional values use only documented defaults, labelled as defaults; unavailable observations stay Unknown. A zero-replica workload or DaemonSet with no scheduled Pods can accept a template change, but review clearly says no current Pods are expected to restart. No inferred completion or healthy status.

Show a concise warning that controller rolling updates are not a guarantee of zero downtime or PDB protection. Explain that external automation may overwrite template changes. Do not scan all Pods, HPAs, PDBs or namespaces to construct an impact estimate. Present observed counts as evidence, not a fixed affected-Pod list. Recreate requires typing the resource name in addition to confirmation; other eligible strategies require the ordinary explicit confirmation. Show no scaling/PVC-deletion warning unless relevant to restart; do not promise storage or application availability.

## Review and navigation

Add **Restart…** next to Scale in supported resource Overview actions, using existing controls and modal. Unavailable eligibility has an accessible reason. The dialog captures connection/generation, cluster label, namespace, API/kind/name, UID and source version. **Review restart** performs preparation; **Confirm restart** sends the opaque token plus required acknowledgement only.

Review shows frozen target, strategy/impact, one changed annotation key, previous value or “not set”, proposed timestamp, expiry and server dry-run warnings. Generate `kubectl.kubernetes.io/restartedAt` as UTC RFC3339Nano once natively during preparation; ensure it differs from the old value (advance one nanosecond if equal). Never regenerate it at execution. Bound displayed previous value to 1 KiB with explicit truncation and escape controls; retain only the bounded source evidence needed natively, never a full manifest across the bridge. Timestamp is a trigger, not proof of observed restart time.

Changing source/resource/namespace/tab/generation, refreshing, closing or editing review invalidates/revokes the pending token. Late prepare replies are discarded/revoked. Native modal prevents background interaction; test programmatic invalidation as well as actual Escape/focus behavior. Escape returns focus to the trigger where it exists. A dispatched operation survives navigation, remains bound to its target and is not cancellable as though unsent.

Extend the existing app-level result surface from Scale results to **Operation results**, distinguishing Scale and Restart rows. Keep original counts for scale; restart rows show the requested annotation time and outcome. No new Sessions dock. Accepted means the API accepted the template patch, not that all Pods restarted or became ready. Open target revalidates UID, refresh is read-only, and Back preserves existing behavior. Never convert Unknown to proven success just because the annotation later matches. No automatic rollout watcher in this phase.

## Native API and security contract

1. Only fixed `/apis/apps/v1/namespaces/<namespace>/{deployments,statefulsets,daemonsets}/<name>` routes. Native target/name/scope/UID/version validation precedes I/O. Generic discovery remains read-only. Use guarded REST config and the existing bounded, non-replayable operation HTTP transport.
2. Preparation GETs the exact parent, checks identity/version against the displayed capture, termination and eligibility, and extracts safe strategy/count evidence. Full parent responses may contain sensitive literal values: keep them native, bounded and ephemeral; never forward/log bodies or expose a full diff. JSON parsing must preserve unknown fields and number tokens when comparing specs, not round-trip through float64 or incomplete typed structs.
3. Request a SelfSubjectAccessReview for `patch`, group `apps`, exact parent resource/namespace/name, with no subresource. Preserve scaling's Allowed/Denied/Unknown rules: successful explicit deny blocks; request-level denial, unavailable/evaluation-error/undecided hint is Unknown, not authorization. Actual reads and dry-run still enforce server permissions. No permission probes that mutate persisted resources.
4. Build a fixed JSON Patch (`application/json-patch+json`) with `test /metadata/uid` and `test /metadata/resourceVersion`, followed solely by the Pod-template annotation change. Escape the key as `kubectl.kubernetes.io~1restartedAt`. If annotations are absent/null, add the annotations object at `/spec/template/metadata/annotations`; if the map exists, add/replace only its key. Validate template/metadata shape; reject malformed structures. Preserve all sibling annotations/labels/spec fields. No arbitrary frontend patch/URL/headers, strategic merge fallback, unconditional retry or field-ownership force.
5. Send one mandatory server dry-run PATCH with `dryRun=All`. Validate returned identity and requested annotation; compare its spec semantically to the expected original spec with exactly that annotation change. If admission changes other spec fields, reject the preview with a safe explanation, no raw sensitive diff. Ignore expected server metadata/status changes for this spec comparison. No fallback when dry-run is unsupported. Capture bounded sanitized warning headers and preserve the original live UID/version, never the dry-run response version as a refreshed baseline.
6. Issue a five-minute token bound to action type, target, source version, exact patch bytes, strategy/impact and acknowledgement requirements. Retain patch and safe projections, not entire parent responses. Execution atomically consumes the token, checks acknowledgement natively, revalidates current parent identity/version/eligibility, then sends the exact prepared patch once without dryRun. Preconditions in the patch cover changes after the last GET; prove enforcement against real API servers. Any version change requires a fresh review. No new timestamp on execution or retry.
7. A successful response must match identity and show the requested marker. If success decoding/identity/marker validation fails, outcome is Unknown because the server may have persisted something. If a valid successful response shows additional admission changes, report Accepted with a bounded “server response differs from reviewed spec” notice; do not claim only the reviewed field changed or attempt rollback. Compare using a hash of the canonical expected spec retained natively rather than retaining an entire sensitive manifest. Unknown numeric fields must remain exact during canonicalization.

## Shared execution boundary and outcomes

Extend the scaling implementation with only the common machinery needed by two actions: a native operation coordinator for pending-token capacity, per-target execution locks, result retention and replay lookup. Keep action-specific inspection/permission/payload functions separate. Scale and Restart must share a target lock (connection generation/API/kind/namespace/name/UID, not action) so they cannot both dispatch against the same target concurrently. Bind token action and reject calling ExecuteRestart with a scale token or vice versa without consuming another action's valid token. A shared coordinator must preserve current scale behavior and marker experiment isolation.

Aggregate limits across Scale+Restart: 128 pending reviews, 16 preparation slots, four executing operations, one active operation per exact target, 100 terminal summaries with active records never evicted, ten-minute completed token lookup and five-minute review expiry. Request deadline 30 seconds, decoded body 16 MiB, bridge output 2 MiB, patch 16 KiB, warning text 8 KiB. Clean up pending reviews on expiry and connection close; avoid per-action budgets accidentally doubling aggregate limits. No persistence or durable audit claim.

Use existing states: executing, accepted, rejected, stale, cancelled-before-send, unknown. Explicit server rejection stays rejection; stale/missing target or failed UID/version precondition is stale where verifiable. JSON Patch test failures may be reported as 422 rather than 409: a subsequent bounded GET may establish stale identity/version; otherwise keep a safe rejected result without parsing/logging arbitrary server body text. This diagnostic GET cannot trigger a retry. Post-dispatch timeout, connection loss, malformed success or ambiguous 5xx is Unknown. Do not automatically replay on any response, including 429, redirect, authentication transport retry or bridge failure. Inspect lower HTTP layers and assert wire request counts.

Revocation and dispatch use atomic first-wins semantics. View cancellation cannot cancel a dispatched native operation; shutdown/connection closure after dispatch may leave an unknown outcome. Repeated Execute returns the existing retained result for that action/token or an expired/unknown-token error, never another request. Result retrieval/listing after UI remount does not execute. Keep terminal outcomes across navigation, discard only according to the bounded session policy; app restart does not restore a guarantee of prior outcome. Preserve scale result evidence and lifecycle fixes from 1D.1.
