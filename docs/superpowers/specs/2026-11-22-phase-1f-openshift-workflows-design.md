# Phase 1F · Dedicated OpenShift workflows

## Outcome and baseline

In one connection, select a visible Project, inspect a Route and its backing Service, follow a Build and its output, then inspect an Operator and review changes to its installation. Each screen works independently under restricted access. OpenShift is optional for ordinary Kubernetes work. The [roadmap](../../roadmap/roadmap.html#phase-1f) owns phase order and exit criteria and the [product requirements](../../product/requirements.html) own capability scope.

This is the umbrella contract for all four workflows. **Projects (1F.1)** shipped in PR #32 at `b5e20c2`. The planning baseline is develop `f92b519`. The [Projects specification](2026-11-22-phase-1f1-openshift-projects-design.md) remains authoritative for visibility, quota/access inspection, UID-bound project switching and reviewed request/delete. Its [pending office acceptance](../validation/phase-1f1.html#office-acceptance) carries forward. New implementation covers **Routes (1F.2), Builds (1F.3), Operators (1F.4)** and the combined journey. Target OCP 4.21 for compatibility validation. Record actual server patch, API versions, provider and installed OLM generations.

## Common behavior

Use the existing OpenShift sidebar group, per-connection discovery, verified project/namespace selection, compact tables and detail, typed operation coordinator, Results and native stream machinery. Discover exact group/version, resource, scope, verb and subresource independently. A missing Projects API must not suppress a served Route, Build or Operator API. In that case use explicit workspace namespace semantics. Remove unavailable destinations from both sidebar and command search. Separate absent, forbidden, incomplete discovery, empty and failed; each section has independent retry. Named GET may work without List. No automatic cluster-wide enumeration to overcome a denied project read.

All reads, related-object navigation, log sessions and writes bind connection generation, namespace, resource identity and, where relevant, selected Project UID. Re-read the source relationship before navigation; references by name open the **current** object and do not prove historical identity. Reuse bounded paging (100/request, up to 500 retained per view), 16 MiB native read ceiling and 30 s request deadlines; respect tighter existing limits. Mark partial inventories and prevent approval based on incomplete impact. Return only projected fields; sanitize untrusted text and use no automatic fetching of hosts, source URLs, images or manifests. Raw build output is sensitive user-requested stream data. Keep it out of telemetry, operation records and validation artifacts.

Review binds the intended action, target, payload and relevant identities to one expiring native token. Recheck authority and freshness before dispatch. User cancellation of review sends zero real writes. Use server dry-run where the owning storage actually honors it. A subresource with server-side effects must never be invoked as a preview or permission probe. Confirm at most once, distinguish acceptance from controller completion, and surface unknown after ambiguous transport. No automatic replay. Keep raw objects, TLS material, build secrets and OLM manifests out of bridge previews and Results. Preserve existing user-initiated generic inspection where allowed by the owning security model; audit alternate UI entry points for accidental default disclosure.

## Routes

Serve namespaced route.openshift.io/v1 routes. List host/path, primary backend and a summary of router observations. Detail shows target Service, target port, alternate backends and weights (zero is meaningful), TLS mode, insecure policy, external certificate reference name when present, and per-router admitted condition/status, reason and observed host. Missing or conflicting observations remain visible. Admission alone does not establish external reachability. Follow only same-namespace Service references after validation. Never connect to a displayed host as part of inspection. [OCP 4.21 Route API](https://docs.redhat.com/en/documentation/openshift_container_platform/4.21/html/network_apis/route-route-openshift-io-v1)

Offer reviewed create, edit and delete. Create accepts name, project, optional host/path, primary Service/port, up to three alternate Services with supported weights, and cleartext, edge/default certificate or passthrough modes with compatible fields. Validate against the effective post-edit TLS mode, including passthrough/path restrictions on existing Routes. Preserve named vs numeric port and omitted vs explicit zero weight. Inspect all served TLS modes, including reencrypt. For existing Routes edit supported path/backend/weight/port fields with a narrow conditional patch; show immutable or unsupported fields read-only. Preserve TLS config, custom certificates, keys, annotations and unknown fields byte-for-byte in meaning. Never round-trip a sanitized replacement manifest. No certificate/key import or Secret fetch. Show actual editable fields before review. Guarded patch and named DELETE use UID/version tests; create uses server-generated admission checks and conflict protection. Delete requires typed name and explains loss of ingress, retaining the Service. Screen, review, diff, clipboard defaults, logs and retained outcomes must pass a sentinel private-key non-disclosure test.

## Builds

Serve namespaced build.openshift.io/v1 BuildConfigs and Builds. Show strategy, configured source type, sanitized repository origin/path, revision when present, input/output references, phase, reason and timestamps. Strip URL credentials, query and fragment; omit invalid URLs, embedded Dockerfiles, env values, source secrets, webhook secrets and inline source. Follow status.config/validated references and mark same-name associations; never infer ownership from generated name prefixes. Link exact supported ImageStreamTag or other discovered references with correct namespace, including cross-project references only via an explicit destination and separate authorized read. External image pull specs are descriptive only. [OCP 4.21 workload APIs](https://docs.redhat.com/en/documentation/openshift_container_platform/4.21/html-single/workloads_apis/index)

Open builds/log on explicit selection, scoped to one verified Build, with the existing bounded log buffers, tail/byte limits, backpressure and cancellation on leave, identity change or disconnect. Check Build identity again after opening the name-addressed stream and before emitting its first bytes. Close on observed replacement or lost access; discard buffered output on target changes. No Pod log fallback or automatic previous-build selection. Distinguish pending, unavailable, forbidden, ended and truncated. Opening logs never starts a Build.

| Action | Native contract and evidence |
| --- | --- |
| Start | Review the captured BuildConfig, source/revision policy, run strategy, output and project. Confirm one POST to buildconfigs/{name}/instantiate with a minimal BuildRequest. Use lastVersion when the server enforces it. |
| Rebuild | Review the captured original Build and recorded inputs/output; confirm one POST to builds/{name}/clone. A rebuild may resolve mutable image tags or external source differently. Disable unsupported inputs such as binary uploads requiring new content. |
| Cancel | For an active captured Build, use the 4.21 supported conditional update of status.cancelled on the Build, preserving unrelated fields and UID/version protection. Review and confirm separately; observe phase afterwards. Completion racing with cancellation is an observed outcome. |

Start and rebuild are imperative, name-addressed server actions. Re-read source UID/version immediately before the POST, refuse observed replacement and disclose the residual race between read and dispatch. lastVersion tracks the build counter, not UID. Do not claim atomic source identity. Do not submit dry-run instantiate/clone as review. Show a returned Build identity separately from its later status. No webhook calls, binary uploads or arbitrary build arguments. [Upstream clone handler](https://github.com/openshift/openshift-apiserver/blob/release-4.21/pkg/build/apiserver/registry/buildclone/rest.go)

## Operators

The first dedicated lifecycle provider is **OLM Classic**. Discover operators.coreos.com/v1alpha1 CatalogSources, Subscriptions, InstallPlans and ClusterServiceVersions (CSVs), v1 OperatorGroups and packages.operators.coreos.com/v1 PackageManifests per capability. Catalog namespace, install namespace and OperatorGroup target namespaces may differ: label all three. Make catalog/source selection explicit and limit queries to the selected scope. Show package/channel, current vs installed CSV, approval mode, pending plan, CSV phase/conditions and upgrade status. Show declared owned/required APIs separately from observed managed instances. Offer bounded, permission-aware navigation to selected discovered resources, using ownership or labelled reference evidence and the actual scope. No indiscriminate cluster scan. Detect served OLM v1 ClusterCatalog/ClusterExtension resources by discovery and offer inspection via the generic browser. Distinguish coexistence, Classic-only, v1-only and partial access. Classic write actions require Classic APIs. [OCP Operators](https://docs.redhat.com/en/documentation/openshift_container_platform/4.21/observability/operators/olm-v1) and [OLM v1 extensions](https://docs.redhat.com/en/documentation/openshift_container_platform/4.21/html-single/extensions/index)

- **Install.** Select an existing catalog/package/channel and an existing compatible OperatorGroup in the install namespace. Match PackageManifest status catalog source name and namespace and verify the exact channel before preparing a Subscription. Resolve install modes and effective target namespace set, including all namespaces. Block ambiguous groups or unknown scope. Create only a reviewed Subscription with Manual approval. No new catalog, OperatorGroup or automatic approval. The resolver can add dependencies; installation is pending until its separate plan approval.
- **Approve installation or upgrade.** Capture the actual referenced InstallPlan UID/version, manual approval flag, affected CSVs, package/channel and bounded plan steps. Review all affected resources including dependencies and cluster-scoped RBAC/CRDs even when requested from one project. Project safe identities and scope only. Incomplete resolution, truncated steps, unverified plan reference or unresolved scope disables approval. Revalidate linkage and step contents and patch only spec.approved with identity/version tests. Surface controller status after acceptance.
- **Remove.** Review the Subscription and the installed non-copied CSV plus known dependents, target scopes and ownership limits. Removing a Subscription stops its updates; removing its CSV is a separate explicit reviewed deletion that can stop reconciliation. Never delete shared/copied CSVs, CRDs, custom resources, catalogs, OperatorGroups, dependencies or data as an implicit cleanup. Capture Subscription and installed CSV UIDs before removal. The second review checks the same CSV UID and freshly reads remaining non-copied Subscription references and dependent API evidence across the relevant scopes. Block CSV removal with known dependents or insufficient evidence about sharing. Report partial completion after either step, re-read current references and require fresh review before further writes. No claim that all installed resources disappeared.
- Use server dry-run plus identity/version guards where applicable, typed names for removal and an explicit acknowledgement for cluster-wide impact. Server authorization is authoritative. Never install an operator for KubeSift’s own functioning.

## Acceptance and closure

Complete the cross-workflow journey using real relationships only. A Route–Service relationship does not imply a particular Build or Operator; retain Project scope while navigating explicitly to Builds or Operators. Record API absence and least-privilege failures without breaking other pages. Run deterministic and approved kind tests plus packaged desktop verification. Live compatibility requires separate explicit OCP authorization identifying context, principal, disposable names/namespaces, approved verbs, build inputs/output destinations, operator package/catalog/channel, cluster-wide side effects and cleanup. Read-only permission permits only read tests. No live permission is implied by this plan. Track implementation, local verification and platform acceptance independently. Carry every deferred Projects case into the phase report; never extrapolate controller behavior, router admission, logs or OLM reconciliation from kind fixtures. Phase 1F closes only against the roadmap exit with actual results. [Unified implementation plan](../plans/2026-11-22-phase-1f-openshift-workflows.md)
