# Phase 1D.7 Resource Creation Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans in a separate implementation session. Check off verified steps. One independent whole-PR review after implementation/testing, not routine task reviews.

**Goal:** Normalize generated KubeSift bindings to `frontend/bindings/internal`, then create one explicitly named Kubernetes resource from YAML through discovery, server dry-run and ordinary confirmation, without overwriting an existing resource.

**Spec:** [Phase 1D completion design](../specs/2026-11-16-phase-1d-completion-design.md), shared contracts and 1D.7 section. This plan does not authorize 1D.8 implementation.

**Architecture:** Reuse native lossless YAML parsing, discovery, bounded HTTP transport, draft/review coordinator and editor presentation. Add a named-resource CreateService, collection POST and safe created-identity result. No generic HTTP bridge, local kind permission matrix, new editor dependency or redesign.
