# Phase 1E.5 Node administration implementation plan

> Separate implementation chat: use superpowers:executing-plans. Complete these tasks in order. Check boxes after verification.

**Goal.** Ship reviewed Node cordon, uncordon and graceful drain, including truthful results for blocked, cancelled and partially completed work.

**Architecture and stack.** Go owns the Kubernetes target, permissions, review payload, writes and progress. Reuse the existing operation coordinator, client-go v0.37.1, Wails, generated internal bindings and React detail/results surfaces. The [specification](../specs/2026-11-22-phase-1e5-node-administration-design.md) sets the classification order, confirmation policy, timing, limits and evidence standard. Begin from updated develop containing this package, based on `8a6b649`. Use `feature/phase-1e5-node-administration` in the existing checkout.

## Global constraints and review focus

Use only explicit kind-dev-local-a/b. Never target an actual kind host Node for mutation. Confirm the proof fixture is isolated before testing any mutating path. No new clusters, product agents, external kubectl dependency, direct Pod delete fallback or grace/budget overrides. Keep detailed evidence in ignored local storage and one permanent phase report. Preserve Phase 1E.4 Node history and resource actions.

| Risk | Evidence |
| --- | --- |
| A reused Pod name is evicted after review | Task 1 real server rejects stale UID/version, task 3 rechecks just before dispatch |
| Namespace filtering or incomplete pages hide an unsafe Pod | Task 2 counts cross-namespace Pods, tests pagination failure and zero real writes |
| Scheduling and YAML operations race or a repeat click launches another worker | Tasks 2–3 canonical lock and idempotent token tests |
| Accepted eviction or failed transport is reported as completed | Task 3 separates admission, observation, ambiguity, cancellation and final inventory |
| Navigation hides outstanding work, or fixtures disrupt the shared host | Task 4 mounted UI and task 5 packaged fixture walkthrough |

## Task 3 — Execute, observe and cancel drain

Add CancelDrain(operationID) scoped to the owned operation. Use existing GetOperationResult for individual progress and bounded summaries for result lists; never copy every Pod of every retained operation into a poll. Bound detailed retained records and make expiry explicit.
- [x] Write `TestDrainExecution` with a counting transport and controllable clock. Cover re-review before any write; already cordoned; Pod/owner changes; terminating finalizers; actual and generic 429, Retry-After and deadline; 401/403, conflicts, ambiguous responses, replacement, external uncordon, new Pod at final listing, cancel during a request, and disconnect/shutdown. Assert HTTP verbs, paths, body preconditions, retry counts and absence of DELETE. Replaying the same confirmed token must return the original operation ID without another worker.
- [x] Implement per-connection/global admission atomically with the Node lock. Keep a native cancel handle, snapshot updates under lock and release all workers/timers/locks on every exit. Honor cancellation between every side effect. Bound per-request time inside the total wait. Limit Pod disappearance reads to one per two seconds and use final complete inventory for success. Unit-test that a late UI cancel cannot affect another operation.
- [x] Extend operation DTOs with observed scheduling state, counts, timestamps, reason and rows for remaining work. Distinguish completed, blocked, partial, cancelled, timeout and unknown, including how much changed. Regenerate bindings with `wails3 task bindings`.
