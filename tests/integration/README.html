tests/integration

One opt-in local scenario. Set the exact isolated fixture kubeconfig; no ambient source or external API is accepted. The same opt-in scenario validates prepared marker writes, intervening edits, recreation and generation replacement. Recreation atomically replaces only the recorded A ks-marker UID in the ownership journal; the original marker value is restored. Refresh expired one-hour tokens with the already-authorized fixture setup before rerunning.

explorer_test.go is the opt-in two-cluster product scenario. Set KUBESIFT_EXPLORER_INTEGRATION=1 and an absolute KUBESIFT_EXPLORER_CONFIG_DIR containing a.kubeconfig, b.kubeconfig and restricted.kubeconfig. Run go test -tags integration ./tests/integration -run TestExplorerConnections. Configurations must refer only to the approved loopback clusters; credentials remain ignored.

workloads_test.go exercises read-only Pod/Deployment investigation and log snapshot/follow cleanup. Use KUBESIFT_EXPLORER_INTEGRATION=1 and absolute KUBESIFT_EXPLORER_CONFIG_DIR with a.kubeconfig and b.kubeconfig, then go test -tags=integration ./tests/integration -run TestWorkloadInvestigation -count=1. Only kind-dev-local-a/b loopback endpoints are accepted.
