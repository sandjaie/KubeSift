explorer_test.go is the opt-in two-cluster product scenario. Set KUBESIFT_EXPLORER_INTEGRATION=1 and an absolute KUBESIFT_EXPLORER_CONFIG_DIR containing a.kubeconfig, b.kubeconfig and restricted.kubeconfig. Run go test -tags integration ./tests/integration -run TestExplorerConnections. Configurations must refer only to the approved loopback clusters; credentials remain ignored.

workloads_test.go exercises read-only workload investigation and Pod log snapshot/follow cleanup. Use KUBESIFT_EXPLORER_INTEGRATION=1 and absolute KUBESIFT_EXPLORER_CONFIG_DIR with a.kubeconfig and b.kubeconfig, then go test -tags=integration ./tests/integration -run TestWorkloadInvestigation -count=1. Only kind-dev-local-a/b loopback endpoints are accepted.

networking_test.go uses the same isolated A/B files plus restricted.kubeconfig to verify the existing Service, Ingress, NetworkPolicy and controller-generated EndpointSlice fixtures. Run TestNetworkingInvestigation with the same integration tag and opt-in. Restricted credentials must have the fixture pod-reader rights only; requests check reads, with no fixture writes.

TestConfigurationInvestigation uses the same explicit A/B kubeconfigs plus configuration-restricted.kubeconfig for the ConfigMap-only identity in the isolated Phase 1C.3c namespace. Use the fixture manifest in the explorer fixture directory.

Keep the synthetic scheduled-job CronJob suspended. Before workload validation, create one temporary Job and let it create a Pod in each context using the commands below. The generated Job carries the actual CronJob controller UID. Remove the exact fixture after verification and leave the other fixtures in place. 

for context in kind-dev-local-a kind-dev-local-b; do
  kubectl --context "$context" -n kubesift-explorer create job phase1c3a-retained-job \
    --from=cronjob/scheduled-job --dry-run=client -o json |
    python3 -c 'import json,sys; j=json.load(sys.stdin); j["metadata"].setdefault("labels", {})["kubesift.dev/fixture"]="phase1c3a-validation"; j["spec"]["activeDeadlineSeconds"]=90; print(json.dumps(j))' |
    kubectl --context "$context" -n kubesift-explorer create -f - || exit 1
  kubectl --context "$context" -n kubesift-explorer wait --for=condition=complete \
    job/phase1c3a-retained-job --timeout=120s || exit 1
done

# After validation
for context in kind-dev-local-a kind-dev-local-b; do
  kubectl --context "$context" -n kubesift-explorer delete jobs \
    -l 'kubesift.dev/fixture=phase1c3a-validation' \
    --field-selector metadata.name=phase1c3a-retained-job || exit 1
done
